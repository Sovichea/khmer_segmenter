# Runtime Word Composition

RAC headwords and subentries include long forms that are built from smaller
accepted words. The Python runtime reduces those forms to a sensible word
composition at load time, so segmentation, spellcheck, and completion do not
treat a phrase as one ordinary word.

## Rules

At load time the segmenter excludes a word from segmentation when **all** hold:

1. It is a composition of **≥2 parts**, each an accepted spelling with
   **≥2 orthographic clusters**.
2. Its RAC frequency is below the guard (`composition_guard`, default `5`).
3. It is not in the composition keep-list.

Spelling validity is unchanged: an excluded word is still an exact accepted
spelling, and whole-span validation is available through
`is_valid_composition()`.

```python
segmenter.segment("ក្រុមហ៊ុនមហាជនទទួលខុសត្រូវមានកម្រិត")
# ["ក្រុមហ៊ុន", "មហាជន", "ទទួលខុសត្រូវ", "មាន", "កម្រិត"]

segmenter.is_valid_composition("បុរាណកាល")  # True
segmenter.is_spelling_valid("វាក្យសព្ទ")     # True (exact spelling retained)
```

## Keep-list

`khmer_dictionary_composition_keep.txt` pins forms that are lexicalized even
when transparent. It is generated by `scripts/build_composition_keep.py` from
the pinned RAC source plus the curated layers, and covers:

- RAC `t_main` headwords,
- the supplemental segmentation layer,
- the author-curated, RAC-derived, and RAC-usage review layers,
- `ៗ` repetition forms.

Regenerate it after a model rebuild:

```bash
python scripts/fetch_sources.py
python scripts/build_composition_keep.py
```

When no keep-list is present (custom data), the runtime requires forms of at
least seven clusters before splitting, so a custom dictionary is not
over-segmented.

## Native packs

Python applies the policy at load time. Native consumers read a KDIC pack,
which stores costs but not raw frequencies, so the policy is **baked into the
compiler** instead: `scripts/build_dictionary_kdict.py` clears `SEGMENT` for
composition words and clears `AUTOCOMPLETE` for forms above the cluster cap
before writing the pack. Rust, WASM, and C therefore inherit the same split and
completion behaviour with no runtime work. `scripts/export_rust_language_pack.py`
keeps the base flags and applies the same completion cap to promoted words.

Rebuild the native packs after changing the policy or the keep-list:

```bash
python scripts/build_dictionary_kdict.py
python scripts/export_rust_language_pack.py
cargo test --manifest-path port/rust/Cargo.toml --lib
```

## Completion cap

`complete_word()` limits suggestions by orthographic cluster count
(`max_clusters`, default `5`) so a long curated phrase is not offered as a
completion. Pass `max_clusters=None` to disable the cap.

```python
segmenter.complete_word("សញ្ញាបត្រ")  # only សញ្ញាបត្រ
```

## Opt out

```python
segmenter = KhmerSegmenter(composition=False)
segmenter = KhmerSegmenter(composition_guard=0)  # no word crosses the guard
```

## Verification

On the 300-sentence curated benchmark the runtime policy scores boundary F1
`0.9973` and exact-sentence `95.3%`, versus `0.9970` and `94.7%` without it.

The composition axis is independent of [safe word breaks](WORD_BREAKS.md):
breaks let layout engines wrap a token, while composition decides whether the
token is one unit at all.
